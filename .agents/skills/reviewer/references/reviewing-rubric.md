# Reviewing Rubric(审稿客观规则库)

> 本文件是 `paper-redteam` 所有评审的**客观依据**,从三大会议**官方审稿人指南**蒸馏而来(不是凭印象):
> - **NeurIPS** Reviewer Guidelines(originality/quality/clarity/significance + 评分量表)
> - **ICLR** Reviewer Guide(四个核心问题 + "不必非得 SOTA")
> - **ACL Rolling Review (ARR)** Reviewer Guidelines(评分维度 + **H1–H17 不正当理由黑名单**)
>
> 两种模式(审自己 / 审别人)都以本文件为客观标尺。`reviewer-personas.md` 决定"用什么口吻盯",本文件决定"按什么标准评、什么批评算数"。

---

## 一、四大评审维度(跨会议通用)

任何一篇论文,都从这四个维度评。每条 weakness 都要能归到其中一个维度上。

| 维度 | 在评什么(官方问法) | 典型证据/反例 |
|---|---|---|
| **Soundness / Quality(可靠性)** | "技术上站得住吗?claim 有没有被理论或实验支撑?方法合适吗?作者对自己优缺点是否诚实?" | baseline、ablation、误差棒、显著性、混淆变量、claim 是否超出证据 |
| **Clarity / Presentation(清晰度)** | "写清楚了吗?组织得好吗?专家能照着复现吗?" | 记号混乱、关键定义缺失、图表不可读、复现细节不全 |
| **Significance / Contribution(重要性)** | "结果重要吗?别人会用、会在此基础上继续做吗?推进了 state of the art 吗?" | so-what、可迁移性、是否只是换数据集重跑 |
| **Originality(原创性)** | "任务/方法是不是新的?是不是已知技术的新组合?和前作的区别讲清了吗?related work 引全了吗?" | novelty delta、related work 是否回避最强对手 |

> NeurIPS 把前三个做成**独立 4 分制**(见下),Originality 并入 Strengths/Weaknesses 叙述。ARR 把 Soundness 单列、并把"是否令人兴奋"(Excitement)与可靠性**正交**分开。

## 二、评分量表(按会议;用户指定 venue 就用对应表)

### NeurIPS(默认通用 ML 会议都参照它)
- **Soundness / Presentation / Contribution** —— 各一条 **4 分制**:`4 excellent · 3 good · 2 fair · 1 poor`
- **Overall** —— **10 分制**:`10 award quality · 8 strong accept · 7 accept · 6 weak accept · 5 borderline accept · 4 borderline reject · 3 reject · 2 strong reject · 1 very strong reject`
- **Confidence** —— **5 分制**:`5 绝对确定 · 4 确定但非绝对 · 3 较确定(部分没把握)· 2 愿意辩护但很可能没读懂 · 1 纯属猜测/不在你领域`

### ARR(ACL 系:ACL/EMNLP/NAACL)
- **Soundness** —— 技术可靠性,**低分必须用文字实质论证**;
- **Excitement** —— 主观兴奋度,**与 Soundness 正交**,可不必论证;
- **Overall Assessment** —— 综合推荐(soundness+excitement+novelty+impact);
- **Reproducibility** —— 超参/代码/数据是否足以复现;
- **Ethical Concerns** —— 标记是否需伦理复审(非 desk-reject 理由,除非严重)。

### ICLR
不强制数字维度,要求回答**四个核心问题**:(1) 解决什么问题?(2) 动机/在文献中的定位是否充分?(3) **claim 被支撑了吗?**(4) 意义多大、是否带来足够新知?并明确:**"这不一定需要 state-of-the-art 结果。"**

## 三、Reviewer 2 的"必查清单"(客观版,Soundness 重灾区)

这些是**经得起官方标准检验**的硬骨头——R2 盯的就是这些,每一条都要钉到论文具体位置:

1. **Baseline** —— 最该比的最强对手比了吗?有没有躲开?[钉到实验表]
2. **Ablation** —— 提升归因到哪个部件?多个改动是否捆在一起、无法归因?
3. **统计严谨** —— 几个 seed?有误差棒/显著性吗?还是单次跑赢零点几个点就叫 SOTA?
4. **混淆变量** —— 提升会不会只是更多参数/数据/训练步/调参?控住了吗?
5. **过度承诺** —— 摘要/intro 的大词(general / robust / significantly)被证据撑住了吗?[钉到原句]
6. **樱桃挑选** —— 只报赢的设置?失败案例、超参敏感性藏了吗?
7. **可复现** —— 超参、数据划分、代码/权重是否可得?专家能照着重跑吗?
8. **Related work** —— 有没有回避真正的对手?和最接近的那条线区别讲清了吗?
9. **Novelty delta** —— 相对最近工作的**真实增量**是什么?("这不就是 X+Y 吗")
10. **claim–证据对齐** —— 结论的适用范围有没有超出实验覆盖范围?

## 三·补、真实数据校准:哪些批评真能毙掉论文?(ICLR 2024,n=2956 份公开评审)

我们抓了 ICLR 2024 OpenReview 上 **2956 份真实评审**的 `weaknesses`,按关键词归类,并关联每份的 rating(整体均分 **4.95**,录用线≈6),算出"提到某类批评时,平均分比整体低多少"——**降得越多 = 越致命**。

| 批评类型 | 出现率 | 提到时均分 vs 4.95 |
|---|--:|--:|
| 数据集/任务范围窄 | 1.3% | **−0.77** |
| 过度承诺 / claim 无支撑 | 3.0% | **−0.68** |
| novelty 不足 / 增量 | 19.9% | **−0.60** |
| related work / 漏引 | 18.5% | **−0.50** |
| 无误差棒 / seed / 显著性 | 6.8% | −0.34 |
| 缺与 SOTA / 对手比较 | 28.7% | −0.31 |
| 清晰度 / 写作 | 33.2% | −0.29 |
| 弱 / 缺 baseline | 18.1% | −0.29 |
| 理论 / 证明不足 | 16.4% | −0.26 |
| 缺 ablation | 8.4% | −0.12 |
| **要求"再多做实验 X"** | 3.9% | **−0.02** |

**两条数据结论(直接定评审重点优先级):**
1. **真正毙论文的是"定位类"硬伤**:novelty 不足、related work 没摆好、过度承诺、适用范围窄——比"再多做点实验/缺 ablation"致命一个数量级。**所以 R2 该先咬定位类,而不是一上来就喊"补实验"。**
2. **数据反过来印证了公正性防火墙**:最常被喊的"没超 SOTA"(28.7%)和"该多做实验 X"(3.9%),对结局影响其实很小(−0.31 / −0.02)——正是 ACL 列为 **H5 / H13** 的不正当理由。**别带头用这些当硬伤。**

> ⚠️ 诚实说明:**关键词归类(非语义)**,**单会议单年份(ICLR 2024)**,"降分"是**相关非因果**(差评的 weakness 本就写得更长更狠)。方法与可复现脚本见 [`data/iclr2024-weakness-analysis.md`](./data/iclr2024-weakness-analysis.md)。

## 四、🔥 公正性防火墙:H1–H17 不正当批评黑名单(本次升级的命门)

ACL 官方明令**这些理由不算数**——它们是键盘喷子和合格审稿人的分水岭。
**本技能在任何模式下,提出 weakness 前都要过这道防火墙:命中下列任一条,就不许把它当作硬伤,要么删掉,要么降级为"温和建议"并注明理由。**

| 编号 | 不正当理由 | 为什么不算数(官方依据) |
|---|---|---|
| **H1** | "结果不令人惊讶" | 事后诸葛;看似显然的发现也可能推进认知 |
| **H3** | "结果不新颖" | **必须给出具体引用**;复现/分析类论文也该被公正对待 |
| **H5** | "没超过最新 SOTA" | 超过 SOTA **既非必要也非充分**条件 |
| **H6** | "结果是负面的" | 对负面结果的发表偏见伤害整个领域 |
| **H7** | "方法太简单" | **简单是优点**;解决问题比把它复杂化更重要 |
| **H8** | "没用我偏好的方法论" | 跨学科方法都合法,不该强求某种范式 |
| **H9** | "题目太小众" | 窄子领域也能有重要贡献 |
| **H10** | "只在非英语/某语言上测" | 任何单语种工作都有理论与实践价值 |
| **H13** | "作者本可以再做实验 X" | 论文只需**对自己的 claim** 有足够证据;额外的属"建议",不是拒稿理由 |
| **H14** | "应该和闭源模型 X 比" | 仅当**直接支撑其 claim** 时才合理;还要警惕 LLM 测试集污染 |
| **H15** | "作者应该改用 [X] 做" | 多种合法路径并存;只有当方法**妨碍了回答其研究问题**时才批评 |
| **H16** | "有局限 = 有缺陷" | **主动声明的局限不是拒稿理由**(NeurIPS 亦明确:应奖励而非惩罚诚实披露局限) |

> 用法:当 R2/R3 想提一条 weakness,先自检"这是不是命中 H 列"。
> - 命中 → 这是**不公正**的批评,删除,或改写成"建议(非拒稿点)",并在报告里标 `⚠ 已过公正性防火墙:此点不作硬伤`。
> - 没命中 → 是正当硬伤,保留。
> 这条让本工具**毒得有道理**:它狠,但绝不用键盘喷子的烂理由。

## 五、好评审 vs 烂评审(官方共识,Mode B 审别人时尤其要守)

**好评审:**
- **具体(Specific)** —— ARR 范例:别写"X 不清楚",要写"X 的描述里缺了 Y 和 Z"。引用确切行号/章节、点名缺的引用。
- **公正(Fair)** —— 检查确认偏误、社会偏见、方法偏好;过 H 列防火墙。
- **有用 & 可执行(Useful/Actionable)** —— 给作者能落地改的建议。
- **比例恰当(Proportional)** —— 分清"致命缺陷"和"小改进",别拿小事当大事。
- **善意(Constructive)** —— ICLR 引 Dennett《以善意批评》;ARR:**"写一份你自己也愿意收到的评审。"** 专业、中性,**不挖苦**(匿名权力不对等,口吻要克制)。
- **诚实更新** —— 对作者 rebuttal 要回应;即便没被说服,也说明为什么。

**烂评审(官方点名):**
- "肤浅、外行的评审比没有更糟——只会制造噪声。"(NeurIPS)
- 含糊、无具体可改之处;
- 因格式小瑕疵、或"承认了局限"而扣分;
- 不参与 rebuttal 讨论。

## 六、两种模式怎么用这套规则(速查)

| | **Mode A:审自己的稿(红队)** | **Mode B:审别人的稿(当审稿人/帮导师)** |
|---|---|---|
| 立场 | 找出**我自己**的弱点,越早越好 | **公正裁判**别人的论文 |
| 口吻 | 三个人格对抗式开火(R2 可以暴躁) | **专业、中性、善意**(单份正式评审,守"写你愿收到的评审") |
| 防火墙 | 用它避免吓唬自己(别把 H 列当真硬伤) | **强制**:绝不对作者发出 H 列不正当批评 |
| 产出 | 模拟评审 + AC 预测结局 + **修补清单** | 一份**按 venue 官方表格式、可直接提交**的评审 |
